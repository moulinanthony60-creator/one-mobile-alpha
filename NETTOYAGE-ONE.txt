BASE CONSERVÉE
La page principale reste index.html. Elle charge le bundle one-3d-v218.js.
Le service worker conserve son cache one-mobile-alpha-v221-valdoria-save-v39.
Les jeux Party, 3:17, le dossier royaume (Valdoria), les fichiers serveur/SQL,
les licences et les fichiers de vérification de domaine sont conservés.
Aucun des 732 fichiers d'origine conservés n'a été modifié, renommé ou déplacé.
Aucun déploiement et aucune modification de base de données n'ont été effectués.

Les scripts anciens encore référencés, les ressources chargées dynamiquement,
les modèles 3D et leurs textures externes sont conservés. Les fichiers
index_FIXED.html et index_ONE_IA_corrige.html ne sont pas des copies identiques :
ils restent disponibles, car leur statut ne peut pas être déterminé avec certitude.
Quelques doublons restent volontairement présents : des chemins différents sont
encore utilisés ou la licence accompagne la copie du composant.

ANOMALIES ANTÉRIEURES CONSERVÉES
13 chemins absents existent déjà dans l'archive d'origine : surtout des copies
anciennes à la racine et une page d'aperçu utilisant des chemins locaux.
Une URL relative d'image dans ui/party-premium.css vise également un fichier
ui/ui/one-game-art-96.png déjà absent. Ce contrôle porte aussi sur les fichiers
historiques : il ne signifie pas que chacun de ces chemins est chargé par ONE.
Le détail est dans nettoyage/validation.json. Ces anomalies n'ont pas été
corrigées dans cette opération de suppression de fichiers.

LIMITES
Contrôles statiques uniquement : aucun navigateur exécutable n'était disponible
pour un essai visuel. Les comptes, services distants, caméras, sauvegardes en ligne
et parties multijoueurs n'ont pas été testés. Le code des fichiers conservés
reste strictement identique, mais un chargement de chemin calculé non détecté
ne peut pas être exclu par une analyse statique seule.

UTILISATION
Décompresser et utiliser le contenu de one-mobile-alpha-main comme projet complet.
Pour appliquer ce nettoyage à un dépôt existant, il faut aussi y supprimer les
fichiers listés dans nettoyage/suppressions.json : un simple ajout des fichiers
conservés ne retirera pas les anciens fichiers du dépôt. Conserver les réglages
Git et de déploiement propres au dépôt. Ne pas relancer les scripts SQL ni
redéployer les Workers pour ce seul nettoyage.
Les anciens README, INSTALLATION et rapports présents sont historiques et ne
constituent pas de nouveaux résultats de validation du projet nettoyé.
